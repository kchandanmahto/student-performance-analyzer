
# Security Policy

## StudentIQ Security

StudentIQ is a Student Performance Analytics and Prediction Platform developed under the **CKMHTO.AI** brand.

We take the security of this project and its users seriously.

This document explains how to report potential security vulnerabilities responsibly.

## Supported Versions

Security fixes are generally considered for the latest version available on the `main` branch.

Older versions may not receive security updates.

## Reporting a Vulnerability

If you discover a potential security vulnerability, please report it responsibly.

**Do not publicly disclose the vulnerability before the issue has been reviewed.**

When reporting an issue, include:

- A clear description of the vulnerability.
- Steps to reproduce the issue.
- Potential security impact.
- Relevant logs or screenshots, if safe to share.
- A suggested fix, if available.

## Security Best Practices

Contributors and users should follow these practices:

- Never commit API keys, passwords, or access tokens.
- Never upload private or personally identifiable student records.
- Use synthetic or anonymized datasets for public demonstrations.
- Keep project dependencies updated.
- Validate user inputs before processing them.
- Avoid exposing sensitive information in application logs.
- Review code changes before merging them.

## Scope

This policy covers security concerns related to:

- StudentIQ application code.
- Data processing and prediction modules.
- Model and dataset handling.
- Project dependencies and configuration.
- Deployment-related security issues.

## Responsible Disclosure

We appreciate responsible security research and the effort taken to help improve StudentIQ.

Please allow the maintainer reasonable time to investigate and address reported vulnerabilities before sharing them publicly.
